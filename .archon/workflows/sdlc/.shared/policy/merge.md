# Merge queue policy

This is the SDLC pack's default policy for the merge queue. A project replaces it whole
with its own `.archon/sdlc/policy/merge.md`, which may be nothing more than a pointer to
documents the project already has.

The queue merges on its own when the case is clear, and asks a maintainer when it is
not. The gate is not policy: no pull request merges unless its trusted review verdict
says Ready and CI is green at its head, whatever this document says. The verdict is for
the reviewed commit, and it carries to the head across a clean sync (below).
An open review thread holds the merge only when it raises a defect in what the pull
request changes. A thread on code the pull request doesn't change or make reachable,
such as one that arrived with a merge of the default branch, doesn't hold it.

## Clear: the queue merges

- A bug fix whose change stays inside the defect it fixes and the tests that prove it.
- A small feature: one coherent behavior, a few files, with its tests and docs.
- Tests, documentation and comments.
- A pull request a maintainer approved for merge at its current head, or at an earlier
  head when every commit since is a merge of the default branch with no conflict to
  resolve. A conflict resolution is new work the maintainer has not seen, so it is
  reviewed and asked again.

## Unclear: the queue asks

- Changes to the SDLC pack itself: its workflows, commands, scripts or policy documents.
- A persisted schema, a migration, or any stored or wire format.
- Authentication, credentials or permissions.
- The workflow language: its YAML surface, schemas or validation.
- The plugin protocol, or any contract an outside plugin or provider builds against.
- Large changes: many files or packages, or a rewrite of a subsystem.
- Partial work: one part of a multi-part plan, or a pull request whose review lists
  contract items as not yet met.
- Anything a release or the project's direction depends on without a ruling.

## Before a merge

- **Fix first, ask last.** A pull request that fails the gate for a reason the build
  queue can correct, such as a review thread that raises a defect in the change, a verdict that is not Ready,
  or CI red that the change caused, goes back to the build queue with a brief, whether
  it is clear or not. Ask only when what is left is the decision itself.
- **Merge directly when the merge is clean.** A pull request whose verdict is Ready,
  whose CI is green at its head, and which the forge reports merges into the default
  branch with no conflict merges at that head without a sync, even when the default
  branch moved since. The default branch's CI after the batch judges the combined
  result.
- **Sync first when a clean merge is not enough.** A pull request that conflicts, or
  one that moves, renames or reshapes code across a package (a refactor or a file
  split) or that its review calls cross-cutting, gets the default branch merged in
  before it merges, so its CI judges what the merge produces: a clean textual merge of
  a reshape can still break code the default branch added meanwhile. Only the pull
  request about to merge is synced, once nothing else stops it, with any conflict
  resolved and generated files regenerated by their owning script.
- **A stale verdict gets a delta review, unless only a clean sync moved it.** A pull
  request whose head moved after its review is reviewed again from its last report
  before it merges. A sync with no conflict to resolve keeps the verdict, even when
  the default branch changed files the pull request also touches: the merge wrote no
  new code, and CI at the synced head judges the composed result. A conflict
  resolution, or anyone else's push, is new code and gets the delta review.
- **One rerun for red elsewhere.** CI red in code the pull request does not touch gets
  one rerun of the failed jobs. Red again after it counts as the change's.
- **The default branch comes first.** While its CI is red, merge nothing. After each
  batch, check its CI; red there is raised to a maintainer, naming the pull requests
  merged without a sync since it was last green, so one can be reverted or fixed
  forward.
